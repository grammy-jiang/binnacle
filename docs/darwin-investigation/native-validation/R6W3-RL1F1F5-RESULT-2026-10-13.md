# R-RL1 F1+F5 — pending-exit observability and bounded lock backoff

Isolated Mac worktree: binnacle-chatgpt-rl1f1f5-20261013.
Started from source-bound R6 W3 integration candidate 8bb012a2, not the
production checkout or the suspended Claude Task Manager.

F1: The single-writer Darwin manager now records the first monotonic instant
at which a reaped exit becomes queued but has not yet been written durably.
Its ping extends the existing response with unrecorded_exits (integer) and
oldest_unrecorded_age_s (nullable float). Entries are removed only when the
durable record is acknowledged/removed from the queue. Later retries preserve
the original monotonic age; no job id or command content is exposed by this
summary. Doctor displays a WARN for a nonempty queue but never claims that
the exit was persisted. Busy reaper queueing reports a reason in the log.

F5: On a contested jobs-dir lock, the existing 5ms LOCK_NB polling interval
now backs off by bounded increments within the same monotonic deadline.
The operation still refuses after its original wait budget. This is
starvation mitigation, not a formal guarantee of fairness against external
blocking lock holders. Any loss of ownership remains UNKNOWN.

The additional RPC ping fields are optional and additive; the existing
protocol version and all eight MCP tool schemas remain unchanged.
The new job_manager_queue module holds the small queue methods that were
split only to respect the hard 500-line module limit. The source was not
minified. No service, production record, external process, or live
launchd label is modified by this development.

Affected tests and acceptance commands are recorded in the commit and its
local test log. This candidate still requires source-bound independent
review, cross-platform integration and the final release gate before deploy.

Independent delta-review follow-up:

- Contended lock acquisition now rechecks its monotonic deadline before
  retries and after delayed success, instead of relying on exact wake times.
- Authenticated manager ping also reports manager_python_version and
  manager_waitid_available, so doctor can inspect the actual job owner
  process separately from the MCP frontend interpreter.
- The waitpid ReferenceOwner IPC tests remain runnable on older Darwin
  Python interpreters; real J1 owner tests keep the waitid capability skip.
