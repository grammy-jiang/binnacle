## Decision register and exact contract changes

| Finding | P0.5 resolution and binding design decision | Blocking verification |
| --- | --- | --- |
| R1 — visibility vs authorization | Existing MCP bearer authentication represents one host-authorized principal. Client-name prefixes are **presentation/visibility**, not distinct security identities. The trusted host configuration grants enabled profiles, permitted roots and modes to *all* authenticated callers. Never infer operator or provider privilege from client name. Enforce feature-disabled and profile/root policy in tool-call/domain entry, including direct invocations and unknown clients. If per-client security policy is required later, introduce a distinct authenticated principal first. | Direct tools/call with spoofed/omitted client name cannot elevate host configuration; disabled tool never launches. |
| R2 — provider execution/containment | Separate private research on explicitly trusted, disposable workspaces from publicly advertised READ behavior. A provider executable can read/write/execute independently of the LSP client; validated input paths are insufficient. No READ hint or unattended untrusted-repository enablement until exact provider/argv/env/project config, filesystem/write/cache, network, child creation, and OS isolation are independently measured. Where OS confinement cannot be proven, profile remains `explicit_trust_only` or `benchmark_only`, and public READ registration fails closed. Never promise cleanup of children which deliberately escape process groups. Classify cleanup `verified` vs `unverified` and prevent silent restart or safe-status promotion on uncertainty. | Linux and Darwin native tests for normal close, timeout, cancellation, SIGKILL/crash, unrelated processes and escaped descendants; independent process-tree/writable sentinel evidence. |
| R3 — lifecycle | `application.create_application` alone owns an injected manager; the mounted FastMCP child has **no manager-owning lifespan**. Root startup order is opened File access -> optional maintenance start -> private manager enter (inert; no provider discovery/spawn) -> request serving. Release reverses: stop admission/drain and close manager -> stop maintenance -> File access exit, including startup exceptions and cancellation. Child lifecycle may run but cannot start/close another manager. One successful enter/close per root *ASGI lifespan generation*, not once for all in-memory Client instances. | Forced mid-start failure, concurrent sessions, disconnect/repeated lifespan, close-with-active-futures and process count; actual ASGI service tests before P2 integration. |
| R4 — strict configuration | Reserve `[development_intelligence]` as the only feature top-level section; environment keys use `BINNACLE_DEVELOPMENT_INTELLIGENCE__...`. New nested section/profile models forbid unknown keys, enforce typed ranges and exact identifiers, and validate even when feature is disabled. Because legacy Settings uses `extra=ignore`, add explicit **feature-section typo/near-match** detection without globally changing compatibility semantics for other legacy config keys. An unknown profile/executable field is a startup/configuration error, never a fallback to a project-local command. | Disabled/misspelled TOML and environment cases, invalid profiles and unsafe executable shadowing, explicit precedence tests. Must precede runtime integration. |
| R5 — telemetry/full-capture | The already-shipped `telemetry.full_capture` is opt-in but captures raw MCP request/response/error, potentially including LSP source, hover, diagnostics and exceptions. This is sensitive data; the feature shall never enable it itself. Default sanitized logs include only approved tool label, safe outcome, bounded counts/timing and hashed scope; no protocol frames, source, absolute paths or child stderr. Add new labels explicitly to sanitizer when a public tool is approved. Full-capture data is never imported into eval fixtures or committed; its host-specific protection and retention remain the separate logging workstream. | Tests with capture both off/on, successful and denied requests, traceback and unsafe provider outputs, plus no raw content in ordinary logs. |
| R6 — startup import registry | Server bootstrap imports its fixed runtime module set regardless of whether a tool is mounted. Every Development Intelligence module in that inventory must import without third-party server binaries, platform-only native adapters on the wrong host, filesystem probes or process spawn. Keep optional provider imports behind explicit invocation and audited profile discovery. Regenerate the startup inventory in the implementation package and run both-OS fail-closed import gates. | Provider-uninstalled and feature-disabled startup import checks, module inventory generator, Linux/Darwin no-eager-launch tests. |
| R7 — gate/status/evaluation | P1.1 existing fake fixture is a **provisional isolated foundation**, not evidence of P0 GO or runtime authorization. Only independently accepted P0.5 can authorize future P1 tasks. Before any P4 A/B runs, freeze numerical correctness non-regression, wrong-definition tolerance, benefit threshold, task/sample-size plan, variance/confidence strategy and RAM/CPU budgets in a versioned evaluation manifest; do not choose thresholds after observing results. `search_code_structure` and `analyze_change` remain separately gated private candidates. | Review signed GO/REWORK after amendments; later pre-registered A/B and distinct P5/P6/P7 ship gates. |

## Empirical evidence on the isolated branch

- Five LSP-only cherry-picks applied cleanly atop `40aafcd`, adding 25 files; no baseline production source modification.
- Locally installed FastMCP `4.1.0` and MCP `2.3.0`; Python `3.13.16`.
- The temporary in-memory mount-only lifespan probe observed `root.enter -> child.enter -> child.exit -> root.exit` per local client context. A second context repeated the same sequence; mounting alone caused no entry. This is **not** proof of production ASGI lifespan or process-manager correctness.
- The unchanged selected tests (fake LSP plus server composition, tool surface, visibility and token contracts) returned **38 passed / 10 skipped** on macOS.
- `scripts/check_architecture.py` returned **259 modules checked / 0 reverse dependency failures**; startup module generator `--check` succeeded; import linter reported **25 contracts kept / 0 broken**.
- The live `Settings` loader accepted and ignored a deliberately misspelled top-level `development_intelligenge` key in a temporary in-process probe; this is a design risk, not a newly introduced production behavior.
- Neither real LSP provider, Linux host, ASGI lifespan, network confinement nor adverse process cleanup was exercised.

## P0.5 final decision and limits

The independent follow-up reviewer checked all seven amendments and issued **GO at the SPEC/PLAN level for P1 private fixtures only**. The GO does **not** approve a public MCP tool, an untrusted repository process, READ annotations, live deployment, or P2 runtime integration without its later safety gates. Non-intrusive P0.6 host inventory and P1 private fault-fixture work are now eligible; this conversation intentionally stops before those stages.
