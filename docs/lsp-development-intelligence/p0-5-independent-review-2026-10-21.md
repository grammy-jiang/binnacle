# P0.5 independent read-only review — 2026-10-21

Reviewer: locally installed Codex CLI, read-only sandbox, medium reasoning effort. Input: isolated LSP branch at `2d21845` against upstream master `40aafcd`. The review text is retained with only link targets rebased to this document's directory. Its findings apply to that pre-amendment commit and must not be mistaken for a post-amendment sign-off.

**Verdict: REWORK for P0.5.** The focused-child architecture is viable, but several contracts need resolution before implementation proceeds. These are design gaps, not demonstrated production LSP defects; this branch adds no production LSP runtime.

Verified locally: clean working tree at `2d21845`, five commits above `40aafcd`, with changes confined to documentation and fake-LSP tests.

1. **Authorization must be separated explicitly from client visibility.** The ADR correctly warns that unrestricted clients see every mounted tool ([ADR:25](adr-0001-focused-subserver.md#L25)). Current visibility uses client-supplied names and defaults to unrestricted; authentication supplies one shared `binnacle-tunnel` identity ([identity.py:43](../../src/binnacle/mcp/identity.py#L43), [visibility.py:37](../../src/binnacle/mcp/visibility.py#L37), [application.py:224](../../src/binnacle/application.py#L224)). The design’s “permitted explicit invocation” therefore needs a defined authority source. **Required:** state whether every authenticated caller receives the same host-configured grants; bind executable trust, permitted roots and provider permissions to those grants, never client-name prefixes. Test missing/changed client identity and direct `tools/call`, including disabled tools.

2. **Provider confinement and descendant cleanup remain unresolved architectural prerequisites.** The design acknowledges that input-path validation does not constrain provider filesystem access, but permits “explicitly audited behavior” as an alternative to isolation ([design:59–66](functional-technical-design-v2.md#L59)). It simultaneously promises no orphaned children, including providers that create new sessions ([design:43–45](functional-technical-design-v2.md#L43)). Existing Darwin production instructions explicitly disclose that new sessions/process groups are untracked ([application.py:151–157](../../src/binnacle/application.py#L151)). **Required:** specify per-OS enforcement or narrowly supported provider behavior, denied filesystem/network/process operations, and fail-closed handling where enforcement is unavailable. Separate graceful shutdown from abrupt owner death. Define bounded cleanup success and independently observed descendant accounting; process-group termination alone cannot establish the stated guarantee.

3. **Once-only ownership is stated, but failure ordering is underspecified.** The ADR assigns the manager to the root and forbids a second child-owned manager ([ADR:21](adr-0001-focused-subserver.md#L21)). Current root lifespan nests file access and maintenance cleanup ([application.py:197–211](../../src/binnacle/application.py#L197)); production adds an ASGI wrapper ([server.py:351–362](../../src/binnacle/server.py#L351)). **Required:** define manager acquisition/release ordering relative to these resources and mounted child startup, including partial startup failure, cancellation during close, repeated lifespan entry and concurrent sessions. Acceptance should assert exactly one successful enter/close per application generation, zero launches during composition, and completion of every pending request. The ADR’s FastMCP lifecycle claim is not independently verified by this review.

4. **Strict configuration promises conflict with the current loader.** V2 requires rejecting near-misses but leaves keys provisional ([design:49–55](functional-technical-design-v2.md#L49)). Root settings use `extra="ignore"`; their special unknown-key rejection covers roots-like names only ([config.py:377–382](../../src/binnacle/config.py#L377), [config.py:432–440](../../src/binnacle/config.py#L432)). **Required:** define strict nested provider settings plus detection of misspelled top-level feature sections, TOML/environment precedence, and validation even when disabled. Move this contract before P2.7 configuration/lifespan integration; currently strict profile schema arrives at P3.1 ([plan:59–61](implementation-plan.md#L59)).

5. **Privacy design omits the new full-capture boundary.** Sparse, redacted telemetry is promised ([design:168](functional-technical-design-v2.md#L168)), but current root middleware can capture raw requests, results and exception traces ([logging_middleware.py:144–168](../../src/binnacle/mcp/logging_middleware.py#L144)). Capture is opt-in, so this is **not a default leakage finding** ([config_telemetry.py:27–38](../../src/binnacle/config_telemetry.py#L27)). **Required:** explicitly decide whether full-capture opt-in covers LSP-derived source, diagnostics and rejected requests; test both settings and define retention/export treatment. New tool names also require deliberate sanitized-telemetry integration: otherwise they become `unknown_tool` ([log_safety.py:98–99](../../src/binnacle/observability/log_safety.py#L98)).

6. **Disabled mounting does not isolate startup imports.** Production imports the frozen runtime inventory before composition ([server.py:78–81](../../src/binnacle/server.py#L78)); its generator includes all nonexcluded source modules ([generator:52–60](../../scripts/gen_startup_server_modules.py#L52)), with no optional modules ([startup_imports.py:44](../../src/binnacle/startup_imports.py#L44)). **Required:** specify how disabled installations remain importable without provider binaries or optional client dependencies, update both OS inventories, and test import failures separately from lazy provider unavailability. Unmounted alone is insufficient.

7. **Phase and acceptance records need reconciliation.** P1.1 is marked implemented despite depending on pending P0 GO ([plan:42–44](implementation-plan.md#L42)); the portfolio calls V2 foundations “already approved” ([portfolio:134](development-capability-portfolio.md#L134)). **Required:** classify the fixture as provisional, record actual approval status, and rebaseline stale source references. Before P4 experiments, require a signed acceptance artifact fixing correctness margins, workflow gain, resource ceilings, sample sizing and decision rules; “useful reduction” alone is not executable acceptance ([plan:117](implementation-plan.md#L117)).

**Verification limits:** Static source, document, contract-test and Git metadata inspection only. No edits, builds, installs, tests, provider launches, service inspection, web or GitHub access. Installed FastMCP source was unavailable in this checkout. Runtime once-only behavior, confinement, cleanup and measured product benefit remain unverified.
