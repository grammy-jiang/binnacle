# P3.6 Ed25519 review receipts — offline verifier primitive

**Date:** 2026-10-23. **Scope:** first-party offline verification building
block, not an externally authenticated security review or release authority.

A separate `scripts/lsp_p36_signed_review.py` module verifies a domain-separated
Ed25519 signature over strict, canonical JSON. The receipt binds the reviewer
and producer identifiers, review stage (P3.3/P3.4/P3.5), exact source-artifact
SHA-256, evidence payload SHA-256, target identity SHA-256, timestamp and the
reviewer's signed claim. All unknown or duplicate fields are refused.

## Trust boundary

The verifying caller supplies the **operator-pinned** reviewer identity,
Ed25519 public key bytes, a separately pinned SHA-256 of that key, expected
producer, stage, target digest, evidence digest and actual artifact bytes.
No key is looked up from `trusted_reviewers` supplied within a P3.6 evidence
file, because self-declared reviewer names are not authentication. There is
no downloader, key writer, auto-enrolment, signing endpoint, network call or
MCP tool.

The verifier independently checks the signature, exact bytes, key fingerprint,
producer/reviewer separation, strict schema, and a bounded issue-time window.
It returns a **cryptographically valid signed *claim*** if all tests pass.

**Crucially:** supplying a key and its fingerprint together is not proof that
the key came from an independent trusted authority. This module **cannot
verify the trust-store provenance** and deliberately reports
`externally_trusted_reviewer=false`, `attestations_verified=false`,
`selection=REWORK`, `resource=REWORK`, `read=NO-GO` and
`public_release=NO-GO` even when the *signed claim* says `GO`.

## Tests

The first version has 26 deterministic test cases using a disposable,
in-memory Ed25519 private key generated by the test harness (never written to
the filesystem). Positive and negative tests check:

- Exact canonical signature verification and domain separation;
- Target/artifact/evidence SHA-256 binding and reviewer identity/policy pin;
- Forged signer, altered signed payload, role self-review, invalid Base64;
- Duplicate or additional JSON keys, stale/future timestamps and input bounds;
- Fail-closed outputs which never authorize READ or production release.

There is no user-provided signer key or production reviewer registry connected.
The existing P3.6 raw-artifact consistency preflight continues to produce
`REWORK` with all three stage evidence fields null.

## Next required acceptance work

1. Implement a separate, authenticated, **operator-managed** reviewer public
   key registry outside all agent-writable paths; document explicit key
   rotation and revocation. Public key pins must not originate from the
   subject evidence or a user project.
2. Add independently witnessed, exact-stage artifact importers that prove
   the P3.3 OS sandbox boundary, the P3.4 matching *Pyright* method and
   provider identity, and P3.5 full resource, workload and lifecycle data.
3. Bind all signatures and raw artifact digests to the same immutable
   Binnacle/Git/upstream package identities and replay-resistant run scope.
4. Independently review a complete testable import-and-policy pipeline
   before permitting even private P4 admission. OS confinement and production
   READ remain **NO-GO** regardless of receipt signature success.

No signer keys, production settings, runtime hooks, public MCP tools or
release switches are changed by this work.
