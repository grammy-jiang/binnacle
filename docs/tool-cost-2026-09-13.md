## 4. Benefit side per absorbed call

Corpus: 2565 ChatGPT `run_command` calls. The journal clips a payload at 500 chars (fastmcp appends `...`), so
**70% of commands are cut at about 410 visible chars**; every "visible" figure is a lower bound for those.
Rich wraps the journal column at ~36 chars and drops the space at a word-wrap break; the parser re-inserts it
(all 4731 unclipped payloads parse as JSON afterwards). Breaks that fall exactly on the fold width are ambiguous:
counting them as spaces adds at most 1.8 tokens per call on average. Tokens are counted on the JSON-escaped
string, i.e. as emitted in `arguments`.

| Category (definition in `extract_calls.py`) | Calls | Clipped | Visible command tokens median / mean / p90 |
| --- | --- | --- | --- |
| all run_command | 2565 | 70% | 105 / 94.4 / 133 |
| git, any invocation (`git_any`) | 610 (1378 git invocations) | 55% | 97 / 88.7 / 132 |
| git, every invocation in {status,diff,log,show,blame,ls-files} | 410 | 51% | 98 / 87.4 / 134 |
| git only (+ cd/set -e/printf), no pipes (`git_pure`) | 42 | 12% | 22 / 36.4 / 96 |

| any recognisable shell write (cat/tee, python write, `> file`) | 246 | 96% | 102 / 99.9 / 126 |

Fixed keys beside `command` (`workdir`, `wait_seconds`, `tail_lines`, `background`): median **23 tokens** per

(truncation affects both equally, so the delta holds for clipped calls to about +-1 token):

| Conversion | 1:1 calls | Delta tokens median / mean / p90 | Wrapper text alone |
| --- | --- | --- | --- |

| python edit -> `edit_file(old, new)` | not measurable | - | old/new strings sit in code that is clipped in 94% of calls; the doc's "147 heredoc edits" rule is not recorded (visible markers: write 38, `.replace(`/`re.sub(` 132, `read_text(` 359 of 458 in the 09-07+ window) |

**Result sizes: not measurable.** `tool_result content_chars` counts the text block only, and every tool returns
`ToolResult(content=<one-line summary>, structured_content=payload)` (run_command.py:125/148, read_file.py:205):
measured median 126 chars for run_command and 90 for read_file is the summary, not the output. No result text is
logged. For git and python the output is the same text whichever tool carries it.

| Candidate | Cost per turn | Cost in window (x375) | Absorbed 1:1 calls in window | Saved per call | Saved in window | Saved / cost | Absorbed calls per turn to break even | Measured rate |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

| edit_file + write_file | 319..447 | 119,625..167,625 | 121 (+ python edits, unmeasured) | 11 | 1,331 | 0.011..0.008 | 29.0..40.6 | 0.32 |
| git_query | 221..310 | 82,875..116,250 | 13 single-git (42 pure; 410 all-enum but batched) | -2 | -26 | < 0 | none: no per-call saving on the argument side | 0.03 |

If the schema is re-sent per model invocation (5484 in the window), every cost multiplies by 14.6 and every ratio
divides by it. The comparison is between per-turn schema tokens and per-call argument tokens only; result
tokens and any output-shaping benefit could not be measured (section 4).

**Non-token effects measured (round trips):**

- git batching: a git-carrying call holds 2.26 git invocations on average; 392 of 610 (64%) hold two or more,
  293 pipe git into head/tail/grep/sed, 394 mix in a non-git segment. A one-subcommand `git_query` needs two or
  more calls to replace 64% of today's git calls.
- verification re-reads after shell writes: 26 `read_file` calls within three calls of a shell write of the same
  path (strict path match; 22 of 246 writes were followed by one) over the whole history = 0.07 per turn. The
  09-13 doc's 41 (09-07+ window) used a looser matcher. This is the ceiling on calls a write tool could remove.
- run_python: 748 heredocs move 1:1 (no round-trip change); the 414 mixed ones would split into two calls.

## Caveats

- OpenAI's framing of tool definitions inside ChatGPT is not public: the compact..pretty range brackets it, and
  `title`, `_meta`, `outputSchema`, `annotations` may or may not be forwarded (+923 compact / +1843 pretty for six tools).
- Attribution to ChatGPT is by tunnel timestamp +-2 s; 573 calls that carry `client=openai-mcp` did not match a
  tunnel line and are excluded (same rule as the docs).
- Draft candidate schemas are one plausible shape each; a longer description raises the per-turn cost linearly.
